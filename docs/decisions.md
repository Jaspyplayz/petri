- 2026-10-22 · P2 · The command guard checks every command under two parses: the quote-aware one, which keeps `$(...)` inside its word, and the old one, which splits at `$(`, `(` and backticks. A command is blocked if either parse finds a problem, so a difference between the parser and bash fails closed. Heredoc bodies stay attached to every command on their line, so `cat <<EOF | sh` is caught. The cost is that a commit message quoting an attack must be committed with no other command on that line.
- 2026-10-22 · P2 · The command guard also covers MCP tools whose name suggests they run something (matcher `^(Bash|PowerShell)$|^mcp__.*(exec|shell|command|run|eval|script|terminal|bash|python|code)`). Every string in their input gets the command and secret-path checks. Agents are blocked from a tool that declares a non-shell `language`/`lang`/`runtime`/`interpreter` (JavaScript, Python, …), and from any tool whose name suggests code (python, eval, script, code, node, …), even one that declares a shell language. A declared language only tightens the check, because the agent writes the input and a tool may ignore that field. The guard can't see what files that code writes. A human session allows both. It doesn't match every MCP tool, because document and markdown tools would then trip on prose. Known residuals: a tool with a neutral name that ignores a declared shell language, and scripts written to disk and then run, which aren't parsed. CI's base-branch checks remain the hard gate.
- 2026-10-22 · P2 · Overrides of HOME-like variables (HOME, HOMEDRIVE, HOMEPATH, USERPROFILE, XDG_CONFIG_HOME, CLAUDE_CONFIG_DIR) are a denylist of shell, PowerShell and inline-interpreter forms. It also blocks the ways a name or environment can be built at runtime: computed names, setter calls without one plain literal name, and `env` passed to a spawn. git config writes and `-c` settings are allowlist-only (user.name, user.email, color.*, advice.* and a few more), and whole-section edits are blocked. Inline interpreter code (`node -e`, `python -c`, an interpreter heredoc) that starts another program is blocked outright, because the guard can't see what that program runs. A command whose parsed program word holds a variable or substitution is blocked too, and so is a shell anywhere in a command (after `find -exec` or `timeout` too) given any expansion in its arguments, `%VAR%` included for cmd. In the Bash tool that holds even with no arguments, because bash word-splits `$x` into a whole command. Inside quoted text that may run later, a bare `$x` passes only when it is the whole string (`-m "$msg"`), not one command among several. Any `$` counts as an expansion except at the end of a word or before `/` (sed anchors), because ANSI-C quoting and zsh flags (`$'\x67it'`, `$=x`) outrun a list of expansion characters. The PowerShell tool allows value statements (`$x = …`, `$s -replace …`, a bare `$x`), which can't run a program there. So are `eval` or `source` with expansions and a PowerShell call operator (`& $x`, `iex`, `Start-Process`). git config options are normalized the way git reads them (long-option prefixes, short clusters), and unknown ones fail closed. Known open classes: commands hidden in text that another program runs later (stdin to `xargs` or `sh`, script files, tool variables such as `GIT_SSH_COMMAND`). A denylist over shell and interpreter text can't be complete. Its job is to make the obvious forms fail fast. The worst a missed form can do is skip local git hooks or reach a fake git config, and CI runs the same checks from the base branch. Phase 6 rulesets must also block force pushes to `main`. Further automated-review findings in this class get the cheap fix plus a test; they aren't chased past that.
